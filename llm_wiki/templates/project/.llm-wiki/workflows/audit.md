# Workflow: audit — 품질 감사

목표: Wiki 품질 리포트를 `.llm-wiki/audit/<YYYY-MM-DD>.md`로 생성한다. **문서를 수정하지 않는다 — 보고만 한다.** 시작 전 `AGENTS.md` 규칙을 준수한다.

## 검사 항목

`30_Wiki` 전체 문서에 대해:

1. **깨진 wikilink** — `[[...]]`가 가리키는 파일이 존재하지 않는 경우 (문서·원자료 모두). 위치와 함께 목록화.
2. **출처 없는 핵심 주장** — 근거 섹션이 비었거나 warning callout만 있는 문서.
3. **PDF 페이지 인용 검증** — `#page=N` 인용이 실제 존재하는 페이지인지 표본 확인 (전수 검사가 어려우면 문서당 1~2건 표본, 표본임을 리포트에 명시).
4. **장기 방치 draft** — `status: draft`이고 `created`가 14일 이상 지난 문서.
5. **동일 개념 의심 중복** — 제목·aliases·요약이 유사한 문서 쌍. **병합하지 말고** 후보만 제시.
6. **원자료 불일치** — manifest의 경로에 실제 파일이 없는 항목 (삭제·이동된 원자료)과 그것을 인용하는 문서.
7. **status 유효성** — frontmatter가 깨졌거나 허용 외 status 값을 가진 문서.
8. **코멘트 형식** — `## 코멘트` 항목에 날짜·실명이 누락된 것.
9. **규칙 파일 이중화** — `CLAUDE.md`에 `@AGENTS.md` import 외의 내용이 있는지.
10. **동기화 충돌 사본** — 파일명에 "conflicted copy"·"충돌" 등이 포함된 파일 (Dropbox 등). 본 문서와의 차이를 요약해 보고 (병합·삭제는 사람 결정)
11. **모델 배경지식 검증 대기** — "(모델 배경지식 — 검증 필요)" 표시가 남아 있는 문서 목록 (외부 검증 대상).

## 출력

리포트 구조:

```markdown
# 감사 리포트 — YYYY-MM-DD
## 요약 (항목별 건수 표)
## 1. 깨진 링크
- 30_Wiki/Concepts/문서.md → [[없는파일]] (본문 "## 근거" 섹션)
...
## 권장 조치
- (사람이 할 일을 우선순위 순으로)
```

마지막에 사람에게 요약 보고: 총 발견 건수와 가장 시급한 3가지.

주의: processing-log의 과거 질문·대기 항목을 인용할 때는 **현재 파일 상태를 직접 확인**해 이미 해결된 항목을 걸러낸다 (로그는 이력이지 현재 상태가 아니다).

## 금지

- 어떤 문서·파일도 수정·삭제·이동하지 않는다. 발견한 문제의 "수정 제안"은 리포트에 적을 뿐 직접 고치지 않는다.
